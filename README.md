# QTerm Android

SSH-клиент для Android — порт QTerm для macOS. Общий формат вейлта (.qtvault)
и шифрованная синхронизация между маком и телефоном.

- Терминал на libvterm (termlib), мультисессии, доп-ряд клавиш
- SSH через sshlib, ключи из вейлта, TOFU-проверка ключа хоста
- SFTP-проводник + фолбэк exec/base64 для dropbear
- Редактор (порт QEditor): вкладки — файлы нод, файлы устройства, скрапбук; поиск/замена с regex,
  переход к строке, номера строк, перенос, подсветка; кодировки UTF-8/BOM/1251/KOI8-R/CP866/UTF-16
  и LF/CRLF; строки (дубль/удалить/вверх/вниз/комментарий), формат (trim/сортировка/уникальные),
  Base64/URL/JSON/хеши, откат к сохранённому
- Вейлт под ключом Android Keystore, импорт .qtvault
- Синк: WebDAV / файл в облаке через системный пикер / Google Drive API.
  В облаке только шифротекст: Argon2id + AES-256-GCM, слияние по времени
  правки записи, удаления через tombstones
- Подсказки команд: свой журнал + словарь (свои добавления и скрытия), всё синкается;
  пароли, токены, ссылки с ключами и вставки кода в журнал не попадают
- Сниппеты и команды Git (имя/команда/заметка) — общие с маком и виндой
- «Ноды 3x-ui и AWG» (как на маке и винде): монитор главной и узлов, клиенты × серверы
  (VLESS/Hysteria, сдвоенные), ссылки и QR подписок, синхронизация клиентов по серверам,
  подключение и ревизия нод с планом и галками, переезд на `-SYNC`; AWG — awg-panel и старая
  amnezia-wg-easy: клиенты, конфиги, QR, `.conf`; «Нода из выделения» — итог установщика из
  буфера → новая нода или переустановка (вход по паролю, выпуск API-токена, перепривязка узла,
  пересоздание AWG-клиентов); «Обновления» — версии панелей и Xray, самообновление с бэкапом базы,
  ядро Xray, geo-файлы, восстановление базы и откат версии через SSH-терминал.
  Панели и токены — в вейлте, синкаются с маком и виндой (LWW по времени правки)
- Удержание сессий: foreground-сервис, keepalive, авто-переподключение с бэкоффом
  без потери содержимого терминала
- Монитор ноды (CPU с графиком, RAM, диск, LA, кто залогинен — раз в 3 с, пока открыт экран ноды)
  и «Во все ноды»: по Enter строка с экрана активной ноды уходит целиком во все подключённые
- **QDash — хаб сети** (как окно QDash мака и винды): заведение ссылкой `qdash://enroll` или кодом
  из портала, ключ устройства ed25519 создаётся на телефоне (в вейлте под ключом Android Keystore,
  `sync.qdash:*` — в облако не уходит), каждый запрос подписан, **конверт** — сквозное шифрование
  X25519 → HKDF-SHA256 → AES-256-GCM или ChaCha20-Poly1305; точки входа (локалка → роутер →
  снаружи → KeenDNS → секундант) с пином серта; разделы Обзор / Серверы («Ноды QTerm → в хаб» по
  своему SSH) / Задачи (вывод задач хаба — вкладкой терминала с вводом) / Устройство (шифрование и
  ключи, ключ подтверждения, секундант, точки входа); **портал** — страницы самого хаба вкладками в
  WebView на вымышленном `https://qdash.hub`, каждый запрос перехватывается внутри процесса,
  подписывается и уходит в конверте — ни одного открытого порта; **ключ подтверждения** P-256 в
  Android Keystore (StrongBox, если есть) — опасное подтверждается отпечатком вместо кода 2FA;
  отпечаток/PIN при открытии QDash. Каскад — в портале
- Ключи SSH: экран ключей, вставка приватного ключа из буфера, конвертер PuTTY PPK2/PPK3;
  «Ключи API» — разослать токен на ноды (файл 600 по пути из списка, список синкается)

## Сборка

Нужны JDK 21 и Android SDK (compileSdk 36):

    ./gradlew installDebug

Локальные настройки не в репозитории — положи их в ~/.gradle/gradle.properties:

    org.gradle.java.home=/путь/к/jdk21
    qterm.gdriveClientId=ВАШ_ID.apps.googleusercontent.com

Client id нужен только для бекенда «Drive API» (см. README-GDRIVE.md).

## Обновления и release-подпись

Как на маке и винде: релизы лежат в приватном `Q00000P/QTerm-releases` (теги `android-X.Y.Z`,
файлы `QTerm-android-X.Y.Z.apk` + `version-android.json` с sha256). В APK вшит токен GitHub только
на чтение этого репо; приложение проверяет релизы через 8 с после старта и раз в сутки (выключается в
«О программе»), вручную — «О программе → Проверить обновления…». APK качается по токену, сверяется
sha256 (манифест, иначе digest GitHub; без sha256 — только ссылка на страницу) и подпись, ставится через
PackageInstaller (первый раз Android попросит разрешить «Установку неизвестных приложений»).
Журнал — «О программе → Журнал обновлений» (`filesDir/update.log`).

Поверх встаёт только APK с той же подписью, поэтому релизы подписываются одним ключом
`~/.android/qterm-release.jks`. Debug-сборку (`installDebug`) поверх release не поставить и наоборот —
переход один раз через удаление (вейлт заранее синкнуть или экспортировать).

Один раз:

    ~/dev/QTermAndroid/make-android-keystore.sh

— создаёт ключ (RSA 4096, 10000 дней, alias `qterm`), печатает SHA-1, дописывает в
`~/.gradle/gradle.properties` `qterm.release.storeFile/storePassword/keyAlias/keyPassword`
и по желанию кладёт секреты подписи в GitHub Actions. **Бэкап jks и пароля обязателен.**
Затем — второй OAuth-клиент Google под release-SHA-1 (README-GDRIVE.md, шаг 4б).

Токены — те же, что у мака, в `~/.zshenv` (в гит не попадают):

- `QTERM_UPDATE_TOKEN` — fine-grained, только `QTerm-releases`, Contents: Read-only; вшивается в
  `BuildConfig.UPDATE_TOKEN` (можно и `qterm.updateToken=` в `~/.gradle/gradle.properties`).
  Без него сборка работает, но проверка обновлений отключена с пояснением;
- `QTERM_RELEASE_TOKEN` — Contents: Read and write на `QTerm-releases`, им публикуется релиз.

Релиз с мака:

    ~/dev/QTermAndroid/make-release-android.sh

Или в CI: `git tag android-X.Y.Z && git push origin android-X.Y.Z` (или Actions → android-release →
Run workflow). Нужные секреты репо: `QTERM_KEYSTORE_B64`, `QTERM_KEYSTORE_PASSWORD`, `QTERM_KEY_ALIAS`,
`QTERM_KEY_PASSWORD`, `QTERM_UPDATE_TOKEN`, `QTERM_RELEASE_TOKEN`, по желанию `QTERM_GDRIVE_CLIENT_ID_RELEASE`.
Без ключа подписи `assembleRelease` собирает неподписанный APK, `assembleDebug` не затрагивается.

## Формат синка (QTS1)

    "QTS1"(4) | t(1) | p(1) | m_kib(4 LE) | salt(16) | nonce(12) | AES-256-GCM(JSON)

Ключ — Argon2id(пароль, salt) с параметрами из заголовка (t=3, m=64 МиБ,
p=2, длина 32). Настройки синка хранятся локально и в облако не уходят.
